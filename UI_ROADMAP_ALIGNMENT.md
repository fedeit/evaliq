# EvalIQ UI Alignment Plan

Purpose: track UI changes needed so the prototype reflects both the final roadmap and the feedback/rubric gaps from the commented docs and rubric PDFs.

The prototype should remain centered on the MVP flow: team dashboard -> employee profile -> source-backed prep brief -> post-meeting logger. Roadmap themes should appear as product hooks and labels, not as a full roadmap page inside the user-facing product.

## Group A: Roadmap-Driven UI Changes

These changes reflect the future-product direction from the roadmap. They should make the roadmap feel credible without implying every future project is already built.

### Roadmap Theme 1: Trust Gap

Managers need reliable data and explainable AI briefs before they will use AI output in 1:1s or HR-adjacent workflows.

#### Current UI State

- `PrepBrief.jsx` already has inline numbered citations and a collapsible sources panel.
- `PrepBrief.jsx` still labels the brief as `AI-generated · 24h before 1:1`, which can sound too final.
- `Reports.jsx` uses `AI summary`, which should be softened.
- `UserSettings.jsx` implies additional recipients can receive the same prep brief, which weakens the manager-facing brief position.

#### UI Changes Needed

- Add a trust banner near the top of `PrepBrief.jsx`.
  - Suggested copy: `Draft generated by EvalIQ. Manager reviews before use. Every claim links to a source.`
- Change the prep brief status pill.
  - Current: `AI-generated · 24h before 1:1`
  - Proposed: `AI draft · source-backed · manager-reviewed`
- Add citation helper text near the coverage/source count.
  - Suggested copy: `Click citation numbers to inspect source records.`
- Change `Reports.jsx` heading from `AI summary` to `Draft evidence summary`.
- Add a `Manager review required` pill in `Reports.jsx`.
- Change `UserSettings.jsx` recipient language.
  - Current idea: additional recipients receive the same prep brief.
  - Proposed: `Approved stakeholders can receive summary notifications after manager review.`

#### Do Not Add

- Do not add agent-facing prep brief views.
- Do not imply EvalIQ makes final performance judgments.
- Do not use broad language like `managers trust AI`; use source-backed, editable, manager-reviewed language.

### Roadmap Theme 2: Documentation Gap

The MVP captures notes, but future product work should help managers turn coaching history into review-ready documentation.

#### Current UI State

- `PostMeetingLogger.jsx` captures ratings, notes, and action items.
- `PostMeetingLogger.jsx` currently says `Seeds the next prep brief and the HR write-up at review time.`
- `PostMeetingLogger.jsx` has an `Add to HR file` button.
- `EmployeeProfile.jsx` shows coaching history but does not yet summarize review-ready evidence.

#### UI Changes Needed

- Replace HR-forward logger copy in `PostMeetingLogger.jsx`.
  - Current: `Seeds the next prep brief and the HR write-up at review time.`
  - Proposed: `Seeds the next prep brief and manager-owned review notes.`
- Replace the `Add to HR file` button.
  - Proposed: `Save review evidence` or `Export review notes`
- Add a compact review-readiness panel to `PostMeetingLogger.jsx` or `Reports.jsx`.
  - Fields: last 1:1 note saved, action items captured, source-backed examples available, manager approval status.
- Add a small `Review evidence` section under coaching history in `EmployeeProfile.jsx`.
  - Rows: strength example, concern example, open action item, source count.

#### Do Not Add

- Do not present HR narrative generation as current MVP.
- Do not add fully automated HR submission.
- Do not add PageUp, Workday, or BambooHR export as working current functionality unless clearly labeled future.

### Roadmap Theme 3: Lost Signals Gap

Praise, concerns, goals, action items, and manager observations disappear between review cycles unless the product carries them forward.

#### Current UI State

- `EmployeeProfile.jsx` has coaching history and goals.
- `PrepBrief.jsx` has coaching questions, but not a clear `from last meeting` continuity section.
- `PostMeetingLogger.jsx` says saved notes will seed the next prep brief, but action carryforward is not explicit.
- `Reports.jsx` does not yet show continuity metrics.

#### UI Changes Needed

- Add `Carried forward from last 1:1` in `EmployeeProfile.jsx`.
  - Fields: prior action item, owner, due date, status, `Included in next prep brief`.
- Add `From last meeting` in `PrepBrief.jsx` before coaching questions.
  - Fields: previous action item, what changed since then, suggested follow-up.
- Make post-save confirmation more specific in `PostMeetingLogger.jsx`.
  - Proposed copy: `This action item will appear in the next prep brief until closed.`
- Add continuity metrics to `Reports.jsx`.
  - Suggested metrics: `% action items carried forward`, `open follow-ups`, `stale notes`.

#### Do Not Add

- Do not add public benchmarks.
- Do not add director rollups as a main surface.
- Do not add raw voice-recording analysis.
- Do not add peer/360 feedback; it was explicitly deprioritized due to HR and political risk.

## Group B: Feedback and Rubric Gap Fixes

These changes come from the commented `.docx` feedback and rubric PDFs. They are not necessarily roadmap features; they are corrections to make the current UI match the final MVP argument.

### Gap B1: Buyer/User/Stakeholder Clarity

Feedback source: problem-space comments and cross-cutting final recommendations.

#### Current UI State

- The app generally speaks to the manager, which is correct.
- Some settings and HR-related copy could make HR feel like a primary user rather than a stakeholder.

#### UI Changes Needed

- Keep manager as the primary user in visible product copy.
- Keep agents as downstream beneficiaries, not users of the prep brief.
- Keep HR and IT Director/CIO as stakeholders, not day-to-day users.
- Audit labels in `UserSettings.jsx` and `PostMeetingLogger.jsx` for HR-facing language.

#### Do Not Add

- Do not add agent-facing dashboards.
- Do not add HR as a primary navigation surface.

### Gap B2: AI/HR Accountability and Safety

Feedback source: solution-space comments, roadmap comments, and solution rubric.

#### Current UI State

- Citations exist in `PrepBrief.jsx`.
- Manager approval is implied by `Mark reviewed`, but not emphasized enough.
- `PostMeetingLogger.jsx` still contains HR-forward wording.

#### UI Changes Needed

- Use `AI draft`, `source-backed`, `manager-reviewed`, and `manager-owned review notes`.
- Keep `Mark reviewed` and make it more clearly manager approval.
- Replace `HR write-up` and `Add to HR file` with safer manager-controlled language.
- In `Reports.jsx`, use `Draft evidence summary`, not `AI summary`.

#### Do Not Add

- Do not imply automated HR evaluation.
- Do not imply AI conclusions are final or unbiased by default.

### Gap B3: Goals Scope Control

Feedback source: solution-space comments and final feedback summary.

#### Current UI State

- `EmployeeProfile.jsx` includes a full `Goals` panel.
- The panel is below core evidence, which is acceptable.

#### UI Changes Needed

- Keep goals as supporting context below ticket, call, CSAT, and coaching evidence.
- Consider renaming `Goals` to `Development context` if the panel feels too central.
- Connect goals to action items and future prep, not to the main product promise.

#### Do Not Add

- Do not make goal-setting the main workflow.
- Do not add a separate goals dashboard.

### Gap B4: Integration and Customer-Facing Copy

Feedback source: launch-plan comments and launch rubric.

#### Current UI State

- `TeamDashboard.jsx` says `ServiceNow + Amazon Connect + CSAT · synced 2 min ago`.
- `AdminIntegrations.jsx` names specific tools, which is appropriate there.

#### UI Changes Needed

- Change generic dashboard subtitle.
  - Current: `ServiceNow + Amazon Connect + CSAT · synced 2 min ago`
  - Proposed: `Ticketing + calls + CSAT · synced 2 min ago`
- Keep ServiceNow, Zendesk, Amazon Connect, Five9, Google Calendar, and CSAT email inside `AdminIntegrations.jsx`.

#### Do Not Add

- Do not imply ServiceNow and Amazon Connect are the only supported systems in top-level product copy.
- Do not add ServiceNow Store funnel or CAC logic to the product UI.

### Gap B5: Stronger Value Metric

Feedback source: problem-space comments and final MVP rubric pass.

#### Current UI State

- The final MVP uses `180 hours/year recovered per manager`.
- The prototype does not yet surface this value metric.

#### UI Changes Needed

- Add `180 hrs/year recovered per manager` somewhere low-friction.
  - Preferred placement: `Reports.jsx` metric card or `TeamDashboard.jsx` summary.
- Keep this as a value signal, not a financial calculator.

#### Do Not Add

- Do not add full CAC/LTV math inside the product UI.
- Do not add the old `$660/agent/year` proxy.

### Gap B6: Success Metrics and Evidence Completeness

Feedback source: problem rubric and roadmap rubric.

#### Current UI State

- `Reports.jsx` has report-level metrics.
- `PrepBrief.jsx` has source count and citation coverage.

#### UI Changes Needed

- Add or retain source/evidence completeness indicators.
  - Examples: source count, brief coverage, manager approval status, review evidence available.
- Add review-readiness signals only as support, not as automated HR scoring.

#### Do Not Add

- Do not create a grading/rubric page inside the product.
- Do not add overly precise estimates that look false.

### Gap B7: Scope Discipline From Deferred/Dropped Features

Feedback source: solution comments and final pushback list.

#### Current UI State

- The prototype does not include peer/360, director rollups, public benchmarks, or coaching coach, which is correct.

#### UI Changes Needed

- Keep the MVP route set focused.
- If any future/coming-later item is shown, label it clearly as planned or future.

#### Do Not Add

- Do not add peer/360 input.
- Do not add a coaching coach.
- Do not add director rollups.
- Do not add public benchmarks.
- Do not add raw voice analysis.

3. Add roadmap hooks:

4. Add low-friction value/evidence metrics:
   - 180 hrs/year recovered
   - review evidence/source completeness
